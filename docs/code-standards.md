# 代码规范

本文规定每日金句项目的代码注释与日志要求。新增或修改代码时遵循这些规则；代码审查和收尾时据此检查。

## 注释规范

- 关键流程、业务步骤及不明显的决策必须添加中文注释，说明代码的用途、原因或前后依赖。
- 注释应解释“为什么这样做”或帮助读者理解流程，不重复翻译代码本身；代码变化时同步维护注释。
- Python 模块、公开类和函数使用符合 PEP 257 的文档字符串。文档字符串用中文说明职责；函数文档字符串应在需要时补充参数、返回值、异常及重要副作用。
- 对分页、轮换、并发、重试、Notion 写入顺序和失败恢复等关键逻辑，应在相关代码附近说明约束与安全目的。
- 普通、直观的赋值和简单分支不需要逐行注释，避免注释噪声。

## 日志规范

- 使用 Loguru。关键流程和步骤应记录开始、完成或失败状态，并在有助于诊断时记录耗时、数量、页面或区块标识、重试次数等关键数据。
- 日志应能串联程序的主要执行路径，帮助定位失败阶段及其影响；异常路径记录异常类型或安全摘要，并保留足够上下文。
- 按严重程度使用 `debug`、`info`、`warning` 和 `error`；不要把同一事件重复打印多次，也不要用日志替代必要的异常处理。
- 禁止记录 Notion token、`.env` 内容、认证头或其他凭据。避免输出无关的大段原文、完整 API 响应及可能包含敏感信息的数据。
- 通过配置好的 Loguru logger 输出日志，不使用 `print` 输出程序运行信息。面向用户的命令行结果也应使用统一日志配置。
- 新增关键日志时，检查消息是否包含足够的业务上下文且不泄露敏感数据；必要时用模拟测试验证关键日志会产生。
