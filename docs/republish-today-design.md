# 当天金句原句重发：实现设计

## 目标与边界

当天金句已发布后，Codex 或用户可能修正了 **Notion 金句库中同一条金句** 的标题、原文、原文高亮、位置或链接。提供手动命令，将这条金句的最新展示内容重新写入当天唯一的每日记录和首页。程序只读取已修正的数据并发布，不修改读书笔记、金句库或原稿，也不解析 DOCX。

现有 `qotd daily` 和 LaunchAgent 的 `launchctl kickstart gui/$(id -u)/com.rayliu.qotd.daily` 每次都会重新抽句，不能用来执行本功能。

## 命令与可见结果

```sh
uv run qotd republish
```

- `republish` 自动处理执行时的**北京时间当天**，不接受日期参数；仅在从其他目录运行时才需要与 `daily` 相同的 `--config` 路径参数。
- 成功后，当天每日记录的页面 ID、金句关联、日期、日期标题和轮次保持原值；展示快照与六区块内容刷新为金句库当前数据，首页的受管理六区块同步刷新。命令输出日期、记录 ID、金句 ID、结果和首页链接；失败时返回非零退出码。
- `daily` 的随机选句、轮换与定时配置不变。`republish` 不加入每日 LaunchAgent，不调用 `choose_quote`，不查询候选金句或轮换历史，不创建新记录。
- 若仅修正了读书笔记的摘抄，而对应金句库页面仍是旧内容，先请 Codex 核对并同步金句库，再运行重发。

## 执行流程

1. 复用 CLI 的配置、凭据、日志和首页专用进程锁，计算北京时间当天；在当天没有已发布记录时直接停止，不写入 Notion。
2. 复用首页和管理块结构核验；按当天日期查询每日记录，要求**恰好一条**、状态为“已发布”。校验记录日期、正整数轮次、展示快照结构，以及快照金句 ID 与记录关联一致。没有记录、重复记录、状态不符或数据损坏时停止；不退回 `daily`。
3. 读取该关联 ID 对应的金句页及其唯一关联书籍页。要求金句和书籍未归档，关联与字段可解析；金句可已退出轮换，因为重发不参与抽选。用当前金句库数据生成新的 `Quote` 和六区块负载。校验读取到的金句 ID 仍等于当天记录关联，并在写入前再次确认当天记录仍是原页面和原关联，防止期间被其他流程换句。
4. 保留原记录的日期、标题、关联、轮次和“已发布”状态；只更新展示快照属性及记录的六区块。重发使用独立的 `refresh_record` 写入路径，沿用区块结构保护、内容顺序写入、空白区块跳过和 409 有限重试。记录写完后读回当天唯一记录，确认 ID、关联、新快照和状态一致。
5. 将同一负载写入首页受管理六区块，日期最后写。读回首页六区块并按显示语义核对文本、链接和高亮，再读回记录；一致后才报告成功。任何读回不一致都报错。

Notion 的多次写入不是事务，写入期间读者可能短暂看到新旧内容混合。日志应标明命令模式、日期、记录 ID、金句 ID、写入阶段与耗时，避免记录凭据、完整原文或 API 响应。

## 失败与重试

`republish` 只接受“已发布”的当天记录，重发期间不改变此状态。若记录或首页写入中途失败，退出码为非零；再次运行同一条 `uv run qotd republish` 命令即可重新读取来源并覆盖，始终使用当天记录关联的同一条金句。不会自动改走随机 `daily`。由于 Notion 写入不是事务，失败后状态仍为“已发布”，却可能暂时存在新旧内容混合；此时以命令失败日志为准，重试并完成读回核对，或请 Codex 核查。

## 验收与实施顺序

1. 增加独立的 CLI 分支和发布函数，复用现有 Notion 读写封装；保持 `daily` 行为和 LaunchAgent 参数不变。
2. 离线模拟验证：更正同一金句后重发，记录 ID、关联、轮次及日期不变，快照、记录区块和首页六区块更新；不调用随机选择、不查询候选、不新建记录。
3. 离线模拟验证拒绝路径：当天无记录或有重复、状态不符、快照与关联不一致、源金句不存在或归档、书籍关联无效、首页结构改变；均不得写入。模拟跨越北京时间零点时只处理执行日，不回写前一天。
4. 离线模拟记录写入和首页写入失败；核对失败后不会误报成功，重复执行仍锁定同一关联并能修复部分写入。验证读回不一致会报错，以及 `daily` 既有回归测试。
5. 代码完成后运行 `./docs/init.sh`（pytest、Ruff 检查与格式检查），按项目约定记录实际证据。真实 Notion 验收需在明确写入当天记录和首页的影响后，使用用户授权执行；离线通过不等于线上验收。
